# 900 · 데이터/기타 관리

**메뉴 위치:** 관리자 → 데이터/기타 관리

세션·캐시 정리, DB 마이그레이션·점검입니다. 

이 메뉴의 삭제·보정은 되돌리기 어렵습니다. 최고관리자만 실행할 수 있는 항목이 대부분입니다.

---

## 세션파일 일괄삭제

**경로:** `/adm/session_file_delete.php`

로그인 세션 파일(`data/session/sess_*`) 중 **마지막 접근이 6시간보다 오래된 것**만 지웁니다. 페이지를 **열면 바로 삭제가 진행**됩니다. 끝나기 전에 브라우저를 닫지 마세요. 방금 접속 중인 세션은 보통 남습니다.

디스크가 세션 파일로 가득 찼을 때 씁니다. 일상적으로 누를 필요는 없습니다.

---

## 캐시파일 일괄삭제

**경로:** `/adm/cache_file_delete.php`

최신글 캐시(`data/cache/latest-*`)를 지웁니다. 페이지를 열면 바로 실행됩니다. 목록·위젯이 예전 글을 보여 줄 때 한 번 실행해 볼 수 있습니다. 실행 중 중단하지 마세요. 디자인 CSS 캐시와는 별개입니다.

---

## 사이트 DB 점검/보정

**경로:** `/adm/db_check.php`

화면 상단에 기준 파일(`install/gnuboard5.sql`)과 테이블 개수, DB prefix가 보입니다.

- 없는 **테이블**, 빠진 **컬럼·인덱스** 만 추가합니다. 여러 번 눌러도 됩니다.
- **컬럼 삭제·타입 변경·데이터 INSERT** 는 하지 않습니다.
- 게시판·타임라인의 동적 write 테이블, **모듈 전용 테이블** 은 대상이 아닙니다.

필요할 때 **스키마 다시 확인/보정** 을 누릅니다. 한 번 돌릴 SQL은 [DB 마이그레이션](#db-마이그레이션), 타임라인 자체는 [타임라인 목록](301-timeline.md) 을 씁니다.

---



## 웹 DB 접속

메뉴에 **웹 DB 접속** 이 있으면 외부 DB 관리 도구 URL입니다. 이 설명서 범위 밖입니다.

---



## 자주 하는 일

1. **업데이트 후 화면 오류** → 사이트 DB 점검/보정으로 누락 컬럼 확인·보정
2. **설정이 안 바뀜** → 캐시파일 일괄삭제
